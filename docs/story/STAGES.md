## 2. 세션 시작 절차 (새 세션이 가장 먼저 할 일)

0. **브랜치 확인**: `git fetch origin` 후 **"현재 통합 브랜치"**(아래 한 줄) 위에서 시작한다: `git checkout -B <내 작업 브랜치> origin/<현재 통합 브랜치>`. v6 작업은 브랜치를 따로 두지 않으므로(결정 D4 개정) 끝나면 `main` 에 fast-forward 로 푸시한다(`git push origin HEAD:main`, 세션이 정한 작업 브랜치도 같은 커밋으로 맞춰 둔다).
   - **현재 통합 브랜치: `main`** (단계 0·0②·0b-1·0b-2·0b-3·0b-4·1a·1b 반영됨).
   - 이 줄은 `main` 으로 유지한다. 사용자가 다시 브랜치 검사 방식을 지시할 때만 바꾼다.
1. `CLAUDE.md` → 이 문서 → `STORY.md` → `PROGRESS.md` 순으로 읽는다.
2. 1장 표에서 **다음 대기(⬜) 단계**를 찾고, 이전 단계가 ✅ 인지 확인한다. 아니면 사용자에게 묻는다.
3. `git log` 와 "인계 기록"으로 직전 단계의 결과·미해결 사항을 파악한다.
4. 해당 단계의 3장 항목(목표·범위·완료 기준·검사 항목)만 구현한다. 범위 밖 작업은 하지 않는다.
5. 끝나면: 검증(`npm test`/`build`/`smoke`/`touch`) → 스크린샷(외관·실내 변경 시) → 표·인계 기록 갱신 → `CLAUDE.md` 의 main 반영 절차(버전 올리기 포함)로 `main` 푸시 → 사용자에게 **검사 요청 보고**(아래 4장 형식).
6. 사용자가 고칠 점을 말하면 다음 커밋으로 고쳐 같은 절차로 `main` 에 반영한다.

작업 중 실명이 필요해 보이면 쓰지 말고 `{id}` 자리표시자를 쓴다. 개인 빌드용 실명은 `.gitignore`한 로컬 덮어쓰기 파일에서만 다룬다 (결정 D1).

새 세션 시작용 프롬프트 예시:
> `docs/story/STAGES.md` 의 세션 시작 절차를 따라 다음 단계를 진행해줘.
