## 2. 세션 시작 절차 (새 세션이 가장 먼저 할 일)

0. **브랜치 확인 (새 스레드는 자기 작업 브랜치가 새로 만들어져 시작한다)**: 새 스레드의 작업 브랜치(`claude/…`)는 `main` 에서 갈라져 있어 직전 단계 결과가 없다. 그래서 먼저 `git fetch origin` 후 **"현재 통합 브랜치"**(아래 한 줄)를 읽어 그 위로 옮겨 시작한다: `git checkout -B <내 작업 브랜치> origin/<현재 통합 브랜치>`. 푸시는 내 작업 브랜치에만 한다.
   - **현재 통합 브랜치: `claude/project-thread-0cow9t`** (단계 0 코드 + v6 문서 + 구체화한 계획 포함. 단계 0 이 `main` 에 반영되면 `main`).
   - 단계를 끝낼 때마다 이 줄을 **내 작업 브랜치 이름으로 고쳐** 푸시한다. 다음 스레드가 이어받는 길이 이 줄 하나다. 사용자가 단계를 승인해 `main` 에 병합하면 이 줄은 `main` 으로 되돌린다.
1. `CLAUDE.md` → 이 문서 → `STORY.md` → `PROGRESS.md` 순으로 읽는다.
2. 1장 표에서 **다음 대기(⬜) 단계**를 찾고, 이전 단계가 ✅ 인지 확인한다. 아니면 사용자에게 묻는다.
3. `git log` 와 "인계 기록"으로 직전 단계의 결과·미해결 사항을 파악한다.
4. 해당 단계의 3장 항목(목표·범위·완료 기준·검사 항목)만 구현한다. 범위 밖 작업은 하지 않는다.
5. 끝나면: 검증(`build`/`smoke`/`touch` + 해당 단계 테스트) → 스크린샷(외관·실내 변경 시) → 작업 브랜치 푸시 → 표·인계 기록 갱신 → 사용자에게 **검사 요청 보고**(아래 4장 형식).
6. 사용자가 승인하면 그때 `CLAUDE.md` 의 main 반영 절차(버전 올리기 포함)를 따른다.

작업 중 실명이 필요해 보이면 쓰지 말고 `{id}` 자리표시자를 쓴다. 개인 빌드용 실명은 `.gitignore`한 로컬 덮어쓰기 파일에서만 다룬다 (결정 D1).

새 세션 시작용 프롬프트 예시:
> `docs/story/STAGES.md` 의 세션 시작 절차를 따라 다음 단계를 진행해줘.

**현재 코드 상태 (구체화의 출발점)**

**공통 완료 조건 (모든 단계)**: `npm run build` · `npm run smoke` · `npm run touch` · `npm test` 통과, 스크린샷(외관·실내가 바뀐 단계), 작업 브랜치 푸시, 이 문서의 표·인계 기록 갱신, 검사 요청 보고(4장). 승인 전에는 `main` 에 넣지 않는다.

**공통 제약**: 실명 금지(`{id}` 자리표시자), 매직 넘버는 `src/config.js`, 대사·사건·좌표 데이터는 `data/*.json`, 외부 에셋 금지, 깜빡임 초당 3회 미만, 점프스케어 한 판 3개 이내(R3·R2: E7·E10·E14, R1: E7·R1-f).
