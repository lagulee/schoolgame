## 2. 세션 시작 절차 (새 세션이 가장 먼저 할 일)

0. **브랜치 확인**: 직전 단계 결과가 들어 있는 브랜치에서 시작한다 (1장 표의 "브랜치/커밋"). 단계 0이 `main` 에 반영되기 전까지의 통합 브랜치는 `ccr-63fbf984-5ctv1x` (단계 0 코드 + v6 문서 포함). 새 단계 브랜치는 그 브랜치에서 만든다.
1. `CLAUDE.md` → 이 문서 → `STORY.md` → `PROGRESS.md` 순으로 읽는다.
2. 1장 표에서 **다음 대기(⬜) 단계**를 찾고, 이전 단계가 ✅ 인지 확인한다. 아니면 사용자에게 묻는다.
3. `git log` 와 "인계 기록"으로 직전 단계의 결과·미해결 사항을 파악한다.
4. 해당 단계의 3장 항목(목표·범위·완료 기준·검사 항목)만 구현한다. 범위 밖 작업은 하지 않는다.
5. 끝나면: 검증(`build`/`smoke`/`touch` + 해당 단계 테스트) → 스크린샷(외관·실내 변경 시) → 작업 브랜치 푸시 → 표·인계 기록 갱신 → 사용자에게 **검사 요청 보고**(아래 4장 형식).
6. 사용자가 승인하면 그때 `CLAUDE.md` 의 main 반영 절차(버전 올리기 포함)를 따른다.

작업 중 실명이 필요해 보이면 쓰지 말고 `{id}` 자리표시자를 쓴다. 개인 빌드용 실명은 `.gitignore`한 로컬 덮어쓰기 파일에서만 다룬다 (결정 D1).

새 세션 시작용 프롬프트 예시:
> `docs/story/STAGES.md` 의 세션 시작 절차를 따라 다음 단계를 진행해줘.

## 3. 단계별 상세

공통 원칙: 대사·분기·사건은 `data/*.json`, 이름은 `{gyuha}` 등 자리표시자, 매직 넘버는 `src/config.js`, 파일 400줄 이하, 외부 에셋 금지, 깜빡임 초당 3회 미만, 점프스케어는 한 번의 플레이에서 3개 이내(R3·R2는 E7·E10·E14, R1은 E7·R1-f). 실명은 어디에도 쓰지 않는다.

### 단계 0b-1 — 핸드폰
- 범위: 상태 `{battery, lightOn, screenOpen}`, 시작 배터리 86~92 랜덤(E1 확정 시점에 호출), 확인 −2%, 라이트 20초당 −1%, 보조배터리 줍기(+15%, 상한 100), 0% 처리, 20%·10% 경고, 목표·위치 표시(사건 `objective`·`place`), 2회차 안내(`objectiveRepeat`), 태민 시점 값 55%. **손전등 제거**: `F` 키·터치 🔦 버튼·메뉴 항목을 핸드폰 라이트로 교체하고 `Flashlight` 를 약한 라이트(angle π/6, distance 10~12, 밝기 약 60%, 10% 이하에서 더 어둡게)로 바꾼다. 체크포인트 저장 항목 등록.
- 완료 기준: 배터리 규칙 단위 테스트, 터치에서도 핸드폰 조작 가능, 손전등 흔적 제거.
- 검사 항목: 핸드폰 화면, 라이트 밝기, 터치 조작.

### 단계 0b-2 — 이동·스태미나
- 범위: `controller.js` 에 스태미나(최대 100, 달리기 −12.5/초, 회복 걷기 6·멈춤 12·숨기 15, 1초 지연, 탈진 시 달리기 불가·속도 1.3·30 이상에서 해제), HUD 막대(소모·회복 중에만, 30% 이하 붉게), 핸드폰 화면 열림 시 달리기 불가·이동 ×0.7, 체크포인트 항목, 터치 달리기 연동. 상수는 `config.js`.
- 완료 기준: 스태미나 단위 테스트, 기존 `smoke` 이동 테스트 통과.

### 단계 0b-3 — 추격 엔진
- 범위: gap 모델(`gap += (플레이어 속도 − 귀신 속도) × dt`, 지연 `+= ghostSpeed × 시간`, ≤ 1.5 m 잡힘), 일행 처리 지연(`companionKillDelay`), 출구 열기 연출 시간(`unlockTime`)과 통과 조건(≥ ghostSpeed × unlockTime + 1.5 m), 재시도 시 `startGap` +2 m(최대 +8 m), 체크포인트 재시작, **걷기 위주·평범·최적 세 플레이 자동 시뮬레이션**(기준: 걷기 실패, 평범 도착 거리 4.5~6 m, 최적 10~12 m).
- 완료 기준: 시뮬레이션 테스트가 `npm test` 에 포함되어 통과.

### 단계 0b-4 — 퍼즐 실행기 골격
