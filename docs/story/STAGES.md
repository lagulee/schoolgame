## 2. 세션 시작 절차 (새 세션이 가장 먼저 할 일)

1. `CLAUDE.md` → 이 문서 → `STORY.md` → `PROGRESS.md` 순으로 읽는다.
2. 1장 표에서 **다음 대기(⬜) 단계**를 찾고, 이전 단계가 ✅ 인지 확인한다. 아니면 사용자에게 묻는다.
3. `git log` 와 "인계 기록"으로 직전 단계의 결과·미해결 사항을 파악한다.
4. 해당 단계의 3장 항목(목표·범위·완료 기준·검사 항목)만 구현한다. 범위 밖 작업은 하지 않는다.
5. 끝나면: 검증(`build`/`smoke`/`touch` + 해당 단계 테스트) → 스크린샷(외관·실내 변경 시) → 작업 브랜치 푸시 → 표·인계 기록 갱신 → 사용자에게 **검사 요청 보고**(아래 4장 형식).
6. 사용자가 승인하면 그때 `CLAUDE.md` 의 main 반영 절차(버전 올리기 포함)를 따른다.

새 세션 시작용 프롬프트 예시:
> `docs/story/STAGES.md` 의 세션 시작 절차를 따라 다음 단계를 진행해줘.

## 3. 단계별 상세

공통 원칙: 대사·분기·사건은 `data/*.json`, 이름은 `{gyuha}` 등 자리표시자, 매직 넘버는 `src/config.js`, 파일 400줄 이하, 외부 에셋 금지, 깜빡임 초당 3회 미만, 점프스케어 한 판 3개 이내(R3·R2: E7·E10·E14 / R1: E7·R1-f). 사건의 `objective`·`pov`·`puzzle`·`chase`·`jumpscare` 는 `data/story.json` 에 이미 있으니 그대로 쓴다. 퍼즐·추격 정의는 `data/puzzles.json`·`data/chases.json`, 보조배터리는 `data/powerbanks.json`.

### 단계 0 — 스토리 엔진
- 범위: `data/characters.json`(가명), `data/story.json`(사건 E1~E15 뼈대·대사·선택지), 자리표시자 치환, 플래그(`hasConnectorKey`/`earlyBook`/`dutyCompanion`/`hasExitKey`), 루트 판정(STORY 6장 의사코드), 사건 등록기(같은 사건 연속 발동 금지), 자막·대화창 UI, 선택지 UI(제한 시간·무응답 기본값, 키보드·터치), 상호작용 키(`E`) 재배정과 디버그 키 이동.
- 완료 기준: 실내 맵 없이도 디버그 키로 사건을 순서대로 불러 대사·선택지가 뜨고 플래그가 바뀐다. 루트 판정 단위 테스트(플래그 조합 → R1/R2/R3) 통과.
- 검사 항목: JSON 구조, 대화창·선택지 화면, `E` 키 동작, 터치에서 선택 가능한지.
- v3 보정(2026-10-26): E1 문자·E5 선택지 삭제, 4층 책 상호작용 사건(`interactions`, 디버그 `J`), R1-a~R1-h, E13·E14 루트별 변형, 사건 메타 필드, 퍼즐·추격·보조배터리 빈 뼈대, 엔딩 갱신, `pov` 상태, 체크포인트 `snapshot()`/`restore()`, `endingsSeen`.

### 단계 0b — 핸드폰·배터리·체크포인트 연동·실행기 골격 (v3 신설)
- 범위: 핸드폰 UI(해야 할 것 = 사건 `objective`, 위치 = 건물·층·구역 이름, 라이트 켜고 끄기), 배터리 상태 `{ battery, lightOn, screenOpen }`(시작 86~92 랜덤, 확인 1회 −2%, 라이트 20초당 −1%, 0% 면 꺼짐, 20%·10% 알림), 상수는 `config` (STORY 12장 이름 그대로), 보조배터리 줍기 처리(+15%, 상한 100%, 한 번 주우면 사라짐; 배치 좌표는 맵 단계에서), 체크포인트에 `phone`·`powerbanks` 항목 등록(`runner.checkpoints.register`)과 퍼즐·추격 시작 지점 저장·실패 시 복원 흐름, 2회차 안내(`runner.repeat` → `objectiveRepeat` 표시), 태민 시점 핸드폰(별도 55%, 보조배터리 없음) 전환을 `onPov` 에 연결, 퍼즐·추격 실행기 **골격**(시작·성공·실패 → 체크포인트 재시작 인터페이스와 스크립트 시간표 형식만, 내용은 각 단계).
- 선행: 미해결 (e) 라이트가 기존 손전등을 대체하는 범위(마당 포함 여부)를 **먼저 사용자에게 확인**한다.
- 완료 기준: 맵 없이도 디버그로 배터리 소모·충전·0% 동작, 체크포인트 저장→변경→복원 시 배터리·보조배터리·플래그가 함께 돌아옴. 단위 테스트 + smoke·touch 항목 추가.
- 검사 항목: 핸드폰 화면(PC·터치), 라이트 밝기(너무 밝지 않게), 배터리 수치 체감.

### 단계 1 — 실내 회색 박스 맵
- 범위: 구관(1층 현관, 2층 교무실, 3층 연결문, 4층)과 신관(2층 교실들·배전반, 4층, 5층), 계단, 층별 충돌(2D 충돌에 층 개념 추가), 외부↔실내 장면 전환. 재질·조명은 최소(회색 박스 + 약한 조명).
- 완료 기준: 현관에서 구관 4층, 연결문, 신관 5층까지 걸어서 이동 가능. 스모크 테스트에 실내 이동 항목 추가.
- 검사 항목: 동선·크기·이동 시간(STORY 8장 추정과 비교).

### 단계 2 — 공통 구간 E1~E6
- 범위: E1 진입·조작 안내·핸드폰 확인(지후 책 안내 **없음**), E2 **추격 C1 + 퍼즐 P1**(서진과 함께 복도 도주 → 열린 교실 1곳 찾기 → 라이트 끄고 숨기 → 그림자·검은 연기 통과) 뒤 서진 퇴장(화면 밖 사망), E3 연결문 잠김, E4 교무실 열쇠 + 귀신 원경 목격(귀신 정의는 데이터 `data/ghosts.json`), E5 연결문 개방·계단, 신관 4층 지후 책상 위 책 상호작용 배치(`story.interactions` 의 `dohyeonBook` → `earlyBook`, 목표에 표시하지 않음), E6 5층 책 + 가짜 서진, 이 구간 보조배터리 PB1~PB7 배치, 출구 문 앞 서진 흔적(E2 이후, 기본 깨진 핸드폰).
- 무게: v3 에서 C1·P1 이 더해져 **가장 큰 단계**(추정 21~28분 분량). 필요하면 2a(E1~E2: C1·P1) / 2b(E3~E6)로 나눠 검사받는다.
- 완료 기준: 처음 구간을 끝까지 플레이 가능, C1·P1 실패 시 체크포인트(0b) 재시작. 귀신 인형은 코드로 만든 단순 형태.
- 검사 항목: 처음 구간 분량·긴장감, C1·P1 난이도, 4층 책을 스스로 발견할 수 있는지(너무 숨기지도 드러내지도 않게).

### 단계 3 — E7~E9
- 범위: E7 야자 교실·정전·합류·점프스케어 #1·두 조로 갈라짐, E8 교실 수색 **퍼즐 P3**와 만남(직접 만남 [가정]), E9 4층 책(`earlyBook` 이면 생략), PB8 배치.
- 완료 기준: `earlyBook` true/false 두 경우 모두 진행 가능. 점프스케어 #1 은 큰 소리·번쩍임 안전 기준 준수.
- 검사 항목: 정전·점프스케어 강도, 분기 동작.

### 단계 4 — R3 + 엔딩 C (기본 경로)

### 단계 6 — R1 + 엔딩 A
- 선행: 미해결 (b)(R1 에서 당직 아저씨를 처음 만나는 장면)를 사용자에게 확인한다.
